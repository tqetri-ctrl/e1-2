## 1. 아키텍처 및 데이터 설계

### 1.1 클래스 구조 (OOP 책임 분리)
단일 파일(예: `quiz.py` 또는 `main.py`) 또는 모듈 분리를 고려하되, 콘솔 실행 편의성과 요구조건(최소 2개 이상 클래스)을 명확히 구현합니다.

```
       +-----------------------------------------------+
       |                   QuizGame                    |
       |-----------------------------------------------|
       | - quizzes: list[Quiz]                         |
       | - best_score: int                             |
       | - history: list[dict]                         |
       | - state_file: Path                            |
       |-----------------------------------------------|
       | + run()                                       |
       | + load_state() / save_state()                 |
       | + play_quiz()       (보너스: 랜덤/문항수/힌트)|
       | + add_quiz()                                  |
       | + list_quizzes()                              |
       | + delete_quiz()     (보너스: 삭제 기능)       |
       | + view_scores()     (보너스: 히스토리 기능)   |
       | + prompt_int() / prompt_text()                |
       +-----------------------------------------------+
                              |
                              | 1 : N (관리)
                              v
       +-----------------------------------------------+
       |                     Quiz                      |
       |-----------------------------------------------|
       | - question: str                               |
       | - choices: list[str] (4개)                    |
       | - answer: int (1~4)                           |
       | - hint: str (보너스: 힌트 문구)               |
       |-----------------------------------------------|
       | + display(index: int)                         |
       | + get_hint() -> str                           |
       | + is_correct(user_choice: int) -> bool        |
       | + to_dict() -> dict                           |
       | + from_dict(data: dict) -> Quiz (classmethod) |
       +-----------------------------------------------+
```

### 1.2 영속성 데이터 스키마 (`state.json`)
- 경로: 프로젝트 루트 `state.json` (UTF-8 인코딩)
- 기본 데이터 및 보너스 데이터(힌트, 히스토리)를 모두 수용하는 통합 스키마:

```json
{
  "best_score": 100,
  "quizzes": [
    {
      "question": "파이썬에서 변경 불가능한(immutable) 시퀀스 자료형은 무엇인가요?",
      "choices": ["list", "tuple", "set", "dict"],
      "answer": 2,
      "hint": "소괄호 '()'를 사용하여 생성하며 한 번 생성되면 요소를 변경할 수 없습니다."
    }
  ],
  "history": [
    {
      "timestamp": "2026-11-02 17:35:10",
      "total_questions": 5,
      "correct_count": 4,
      "hints_used": 1,
      "final_score": 75
    }
  ]
}
```

## 2. 미션 및 보너스 기능 명세 매핑

| 구분 | 기능 항목 | 세부 요구사항 및 보너스 구현 내용 |
| :--- | :--- | :--- |
| **기본** | 메뉴 및 콘솔 UI | 1. 퀴즈 풀기, 2. 퀴즈 추가, 3. 퀴즈 목록, 4. 퀴즈 삭제, 5. 점수 및 기록 확인, 6. 종료 |
| **기본** | 안전한 입력/예외 처리 | 앞뒤 공백 제거, 숫자 변환 실패 처리, 허용 범위 초과 검증, 빈 입력 처리, `KeyboardInterrupt` / `EOFError` graceful shutdown |
| **기본** | 파일 영속성 (`state.json`) | 파일 부재 시 기본 퀴즈 5개 자동 생성, 파일 손상 시 JSONDecodeError 잡아서 기본값 복구 및 안내 |
| **기본** | 기본 퀴즈 5문항 | 주제: **"파이썬 & 프로그래밍 기초 상식"** (각 4지 선다, 명확한 정답 및 힌트 포함) |
| **보너스 1** | 랜덤 출제 | `random.sample` 또는 `random.shuffle`을 활용하여 플레이 시 문항 순서를 무작위 배치 |
| **보너스 2** | 문제 수 선택 | 퀴즈 시작 전 풀이할 문제 개수 입력 (1 ~ 전체 등록 퀴즈 수 범위 검증) |
| **보너스 3** | 힌트 및 점수 감점 | 각 문제 풀이 시 `H` 또는 `0` 입력으로 힌트 확인 가능. 힌트 확인 시 해당 문항 점수 일부 감점 (예: 기본 20점 중 힌트 시 10점 인정) |
| **보너스 4** | 퀴즈 삭제 기능 | 목록 번호를 확인하고 원하는 퀴즈를 선택 삭제한 뒤 `state.json`에 즉시 동기화 |
| **보너스 5** | 점수 기록 히스토리 | 단순 최고 점수 외에 플레이 일시, 총 문제 수, 맞힌 개수, 사용 힌트 수, 최종 점수를 `history`에 영구 기록 및 조회 |

## 3. Git 워크플로우 및 커밋 로드맵 (10+ 커밋, 7종 명령어)

### 3.1 Git 기초 명령어 7종 커버리지
1. `git init` (이미 완료됨)
2. `git add` (매 커밋 시 사용)
3. `git commit` (기능 단위 10회 이상 커밋)
4. `git push` (원격 저장소 반영)
5. `git checkout` (브랜치 생성 및 이동)
6. `git merge` (기능 브랜치를 main으로 병합)
7. `git clone` & `git pull` (별도 실습 디렉터리 복제 후 push & 기존 작업 디렉터리에서 pull)

### 3.2 단계별 커밋 시나리오 (총 12~13 커밋)

- **Step 1: 프로젝트 기초 환경 구성**
  - 작업: `.gitignore` 작성 (`state.json` 백업/임시 파일, `__pycache__` 제외 등), 기본 `README.md` 구조
  - 커밋: `Chore: 프로젝트 초기 설정 및 .gitignore 추가` (`git push`)
- **Step 2: Quiz 도메인 모델 구현**
  - 작업: `Quiz` 클래스 구현 (속성: `question`, `choices`, `answer`, `hint`, 메서드: `display`, `is_correct`, `to_dict`, `from_dict`)
  - 커밋: `Feat: Quiz 클래스 정의 및 힌트/직렬화 메서드 구현`
- **Step 3: 기본 퀴즈 데이터 및 영속성 관리자 구현**
  - 작업: 기본 5개 퀴즈 정의, `state.json` 파일 읽기/쓰기, 파일 손상/부재 시 예외 처리 로직
  - 커밋: `Feat: 퀴즈 기본 데이터 정의 및 state.json 입출력 예외 처리 구현`
- **Step 4: 게임 메인 엔진 및 공통 입력 처리기 구현**
  - 작업: `QuizGame` 클래스 뼈대, 메뉴 루프, 범용 입력 검증 함수(`prompt_int`, `prompt_text`), `KeyboardInterrupt`/`EOFError` 핸들링
  - 커밋: `Feat: QuizGame 메뉴 화면 및 안전한 사용자 입력 처리기 구현`
- **Step 5: 브랜치를 활용한 퀴즈 플레이 기능 개발 (Branch 워크플로우)**
  - 작업:
    1. 브랜치 생성 및 이동: `git checkout -b feature/quiz-play`
    2. 기본 퀴즈 풀기 기능 구현
    3. 커밋: `Feat: 퀴즈 풀기 기본 진행 및 채점 로직 구현`
    4. 보너스 미션 통합 (랜덤 출제, 문제 수 선택, 힌트 요청 및 감점 로직)
    5. 커밋: `Feat: 퀴즈 랜덤 출제, 문항 수 선택 및 힌트 감점 시스템 구현`
    6. 메인 복귀 및 병합: `git checkout main`, `git merge feature/quiz-play`
    7. 푸시: `git push origin main`
- **Step 6: 퀴즈 추가 기능 구현**
  - 작업: 문제, 4개 보기, 정답 번호, 힌트 입력 검증 및 추가, 즉시 파일 저장
  - 커밋: `Feat: 퀴즈 추가 기능 및 유효성 검사 구현`
- **Step 7: 퀴즈 목록 조회 및 삭제 기능 구현 (보너스)**
  - 작업: 전체 퀴즈 목록 출력, 인덱스 기반 퀴즈 삭제 및 변경사항 저장
  - 커밋: `Feat: 퀴즈 목록 조회 및 삭제 기능 구현`
- **Step 8: 점수 관리 및 히스토리 기록 기능 구현 (보너스)**
  - 작업: 최고 점수 갱신, 플레이 일시 기반 히스토리 저장 및 포맷팅된 통계 출력
  - 커밋: `Feat: 최고 점수 갱신 및 플레이 히스토리 기록/조회 기능 구현`
- **Step 9: 통합 테스트 및 예외 상황 보완**
  - 작업: 파일 손상 테스트, Ctrl+C 테스트, 잘못된 입력 엣지케이스 점검
  - 커밋: `Fix: 엣지 케이스 입력 검증 및 파일 손상 복구 안내 메시지 개선`
- **Step 10: 문서화 완성 (README.md)**
  - 작업: 프로젝트 개요, 주제 선정 이유, 설치/실행법, 기능 설명, 스키마, 스크린샷 가이드 명시
  - 커밋: `Docs: README.md 상세 프로젝트 문서화 작성` (`git push`)
- **Step 11: Git clone & pull 실습 수행**
  - 작업:
    1. 임시 경로(예: `../e1-2-clone-test`)에 `git clone` 수행
    2. 복제본에서 `README.md` 문구 한 줄 수정 후 커밋 & 푸시
    3. 본래 작업 디렉터리(`d:\cody\e1-2`)에서 `git pull` 수행하여 반영 확인
    4. 임시 디렉터리 정리
